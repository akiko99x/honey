# Support

Use the repository's GitHub Discussions for setup questions, operator advice
and design proposals. Use GitHub Issues for reproducible defects and scoped
feature requests.

Before opening an issue:

1. read `README.md`, `docs/handbook.md`, `docs/error-codes.md` and the focused
   runbook for the affected feature;
2. confirm the problem still exists on a supported release;
3. collect the honey error code, request ID, component versions and sanitized
   logs;
4. remove hostnames, IP addresses, usernames, UUIDs, subscription URLs, tokens,
   certificates, private keys and database credentials.

This community project does not promise an SLA. Security reports must follow
`SECURITY.md` and must never be filed publicly.
